What DejaView does

Every other duplicate finder compares bytes. DejaView compares pictures.

A 1080p film and the 720p copy you made of it share no bytes at all. To a checksum, a hash, or a name-and-size match, they are two unrelated files — so conventional duplicate finders walk straight past the most common kind of duplicate in a real video library.

DejaView watches the footage instead. It reduces each video to a fingerprint taken across its whole timeline, then looks for one file’s footage inside another’s, at any resolution, in any format, starting at any point.

That last row matters more than it sounds. A 480p file upscaled to 1080p has four times the pixels and none of the detail. A tool that ranks by resolution keeps exactly the wrong file; DejaView flags the upscale and demotes it.

And before anything is removed, you see it for yourself: every copy in a group is shown at the same moment of the footage, with its measured time offset applied, so a trimmed copy and a padded copy line up on screen.

Getting started

  1. Click Add a Folder and choose a folder to search. Subfolders are included automatically.
  2. Click Scan for Duplicates. Groups appear as they are found — you don't have to wait for the whole scan.
  3. Open a group to compare every copy at the same moment of the footage, with the detected time offset applied.
  4. Review what's selected, then remove it. The full guide is inside the app under Help › DejaView Guide.

Common questions

Is anything deleted permanently?

No. DejaView never erases a file. Removals go to the Trash, where macOS lets you put them back, or into a quarantine folder beside the original if you prefer that. Every removal is logged first, and one copy in each group is always kept and is never selected for you.

Why is the first scan slow?

Decoding video is thousands of times more expensive than reading a filename, and the first pass has to look at the footage itself. After that DejaView remembers. Every video it has fingerprinted stays remembered by content rather than by location, so a rescan is nearly instant — and a copy of a file you scanned months ago is recognised the moment it appears, even under a different name in a different folder. Byte-identical files are matched without decoding anything at all.

Can I stop a long scan and come back to it?

Yes. Pause saves a resume point, and you can quit the app entirely. Reopen it and the overview offers the unfinished scan. A resume point is also written every fifteen seconds throughout a scan and again when you quit, so a crash or a restart costs a few seconds of work rather than the whole run.

A 480p file was picked as the keeper. Why?

It shouldn't be, and DejaView actively guards against it: it measures real picture detail so an upscaled copy can't win just because it has more pixels. If you're seeing this, check Settings › Keeper — the rule order and the preferred-resolution target are both adjustable, and you may have a target set that prefers a smaller copy. If the settings look right, please write to us with the details.

Which video formats are supported?

DejaView reads video through macOS itself, so it handles what macOS handles: MP4, M4V, MOV and other QuickTime-compatible files. Matroska (.mkv), Windows Media (.wmv) and most AVI files cannot be decoded by macOS at all and are reported as skipped with the reason shown. This is a limitation of the system decoder, not of the matching, and it applies to any Mac app that plays by the App Store’s rules.

What still works on those files: finding byte-identical copies never decodes anything, so two identical MKVs are still found and grouped, and removing one is safe. What is not possible is comparing an MKV at 1080p against the same film at 720p — neither can be looked at.

Note that this is a container problem, not a codec one: the video inside an MKV is usually H.264, which macOS decodes fine. It simply has no demuxer for the Matroska wrapper. If your library is mostly MKV, remuxing to MP4 gets you full matching.

Why doesn’t DejaView convert those files itself?

Because converting a file means decoding it first, and decoding these containers is exactly what macOS cannot do. A built-in converter would fail on precisely the files it was meant to rescue.

What works is remuxing — repackaging the existing stream into an MP4 container without re-encoding. Where the video inside is already H.264 or HEVC, this is lossless and takes seconds per file:

ffmpeg -i "input.mkv" -c copy "output.mp4"

HandBrake does the same in bulk. DejaView’s sidebar has a Copy List of Files button that puts the affected paths on your clipboard with that command, so you have something to work from. Scan again afterwards and the converted copies are fully comparable.

Why can't DejaView see one of my folders?

The app is sandboxed, so it can only read folders you have explicitly chosen in the folder-picker. Use Add a Folder to grant access. If a folder lives on an external drive that wasn't connected at launch, plug it in and add it again.

It found matches I don't think are duplicates.

The matching thresholds are adjustable under Settings › Matching. Raising the required containment makes the app stricter. Nothing is removed without your say-so, so a false match costs you nothing but a glance.

Reporting a problem

The most useful thing you can send us is the app's own diagnostics file. In DejaView:

  1. Open Activity Log from the menu bar (or press ⌘L).
  2. Switch to the Technical log tab.
  3. Click Save Diagnostics… and choose where to save it.
  4. Attach that file to your email.

It contains your settings, the technical log, and the crash report if there is one — which is usually enough to identify the problem without a back-and-forth. It may include the paths of files that were scanned, so have a look at it first if that matters to you. It is never sent anywhere automatically.
